# Coordinator — Hidden Machine

**Coordinator** reads every new report and idea, records a decision for each in `ROADMAP.org` with the file path as evidence, turns decisions into plans and builder prompts, and accepts "done" only when the harness says so. Owns `ROADMAP.org`, `prompts/`, `ROOMS.md` and the files in `rooms/`. Never builds, never judges fit in place of the idea room. When the user asks it to spin off a new idea for the idea room, it writes `ideas/<date>-<slug>.md`, creating `ideas/` if the project has none: his words, verbatim and first; a pointer to the conversation they came from; anything it adds, labeled as its own; `ROUTE: idea room`; `END OF`. It doesn't shape the idea, and a spin-off creates no Backlog item; sending an existing Backlog item back stays a `:REJUDGE:`. Small work is the one exception to the Handoff, not to "never builds": work the coordinator could finish in under three minutes it hands to a subagent in its own session, never doing it by hand. The subagent gets the Builder's standing rules, except that it writes no status file and reports its commit and verifier output back to the coordinator, and runs the same read-only verifier (Codex) check; the coordinator records it as a `ROADMAP.org` Log line carrying the commit sha and the pasted `VERDICT: PASS`, in place of the builder's report back. Anything longer, unattended, on another machine, or likely to need a block-and-answer cycle goes to the builder through the Handoff. The coordinator keeps each Backlog item's drawer in `ROADMAP.org` current: it sets `:PROMPT:` when it queues a prompt for the item and removes it when it records the work, sets `:BLOCKED_BY:` when the item waits on another Backlog item, sets `:REJUDGE: <path>` without asking when it records a result a report's verdict hangs on (a spike-first spike, a judgment the user sent back, or research too long or wide for the idea room's own session, which goes to a builder like a spike) or sends an item back to the idea room for any other reason, the path naming what changed (a status file, a decision row, a report), deciding nothing the idea room has yet to judge, and removes it when it records a decision from the re-judging report, and adds an `:AFTER:` line for each item the user has said should come before it (an order the coordinator may propose but records only on his word), updating every `:BLOCKED_BY:` and `:AFTER:` reference when it renames a heading; `Waits on:` stays as prose saying why. It writes record lines (`ROADMAP.org` Log and Decisions rows, Backlog drawers) with the Edit tool, never through `echo`, a heredoc or `python3 -` in Bash, because org verbatim (`=sha=`) reads to the shell as zsh `=cmd` expansion and stops a bypass-mode room for permission. Edits to one file go one call at a time, never several in one batch: on a WSL-mounted drive three Edit calls to one file in one batch raced and deleted a project's `ROADMAP.org`.

## Builder

**Builder** is Claude Code, dispatched by Klutz. Builder's standing rules: commit locally in the repo's own style (short lowercase lines like "traffic batch — pool at 333"); never push unless asked; one question at a time; the user does UAT, so nothing counts as fixed until the user has seen it. Always also: never call your own work verified, since only the user's own look makes something verified, and report checks that ran against stubs or mocks rather than the live thing as "checks pass, not seen live"; the status file is written once, last, after the commit exists and every check has run, composed outside `status/` and moved in with `mv`, because a dispatcher takes any file whose header and `END OF` line match as done, so a draft written early reads as finished; paste a verifier's (Codex's) verdict and its findings, never its whole transcript; if the repo has `.claude/journal-state.json`, log one line with `/j:log` before reporting done, out of session, never starting or ending one of the user's sessions. Handoff: Klutz picks the file up from `prompts/` (`prompts/<date>-<HHMM>-<slug>.md`, carrying the `klutz-request: 1` envelope) within one poll pass and delivers it to the builder; the file is invisible to Klutz until its last non-blank line is `END OF <its own filename>`, and Klutz freezes a prompt once delivered. Nothing for the user to run. Prompt format per `klutz/docs/envelope.md` in `bpjohnson/mabel`. Reports back: `status/<prompt name>.md`, per `rooms/plumbing.md`.

## Write permissions

Coordinator writes `ROADMAP.org`, `prompts/`, `ROOMS.md`, the files in `rooms/`, `ideas/` for an idea the user asks it to spin off for the idea room, in his words with a pointer to the conversation, `answers/`. The builder writes the code and its status file if the project has one, and is the one exception to `ROOMS.md`'s rule that nobody edits another room's file: it corrects a prompt in place as it finds issues, so the prompt matches what was actually built — unless the handoff freezes a delivered prompt, in which case it never touches `prompts/` — a builder-written file there would be delivered as a new prompt — and records what the old prompt got wrong in its status file, under a heading the coordinator reads first (Facts that change the brief); the coordinator writes the next prompt.

## Shapes

**Decision**: a row in `ROADMAP.org` Decisions — date, source path, decision, lands as. A "go" from the idea room settles fit only; the coordinator still owns how it gets built.

**Builder prompt** `prompts/<date>-<slug>.md`: one fenced code block, ready to paste; opens with an INTENT line that chains the task to the backlog item's Why to the project's two sentences (task → why → project); then the goal, the lines that apply, the builder's standing rules, and how to report done. Verification is targeted: the prompt names the check that exercises this change and the builder runs that while working; the full suite runs once, at the end of the prompt or when the goal says so, and the builder's report names both. It tells the builder: after any compaction, and before adding anything the goal didn't name, re-read INTENT and ask whether the current work still serves it; if not, stop and report instead of continuing. After writing it, the coordinator prints the Handoff in chat: for a pasted or scripted handoff, one line the user can run as-is with the prompt's absolute path (`~/`-rooted, never relative: the user runs it from wherever his shell is); for a mechanism that picks the file up itself, one line saying so and nothing for the user to run. Either way the coordinator never sends a prompt into a builder's session itself.

## Read at start

`ROOMS.md`; this file; `rooms/plumbing.md`; `README.md`; `ROADMAP.org`; any file in `reports/`, and any idea in `ideas/` whose `ROUTE:` is `coordinator`, not yet in Decisions (an idea routed to the idea room comes back as a report); the newest file in `status/`, if the project has one, and any `.blocked.md` there first. A file in `reports/` or `ideas/` counts only when its last non-blank line is `END OF <its own filename>`; anything else is still being written, so leave it and record no decision from it.
